迷宫规模与耗时

每个尺寸使用 20 个固定种子。每个种子预热后重复计时，曲线取各种子平均单次耗时的中位数。求解使用同一张 Kruskal 完美迷宫，起点和终点分别为左上角和右下角。

      横纵轴均为对数刻度。两种递归实现仅测到 50 × 50，以控制栈溢出风险。

      查看各尺寸耗时（µs）

      环路如何影响路径长度

      环路比例指在完美迷宫中额外拆除的剩余内墙比例。每个比例汇总 50 × 50、100 × 100、200 × 200 三种尺寸，每种尺寸使用 20 个种子。

      环路比例迭代 DFS 路径长于 BFS样本占比

      时间与辅助空间复杂度

      N 为格子数，E 为候选内墙数。四邻接网格上 E = O(N)。下表给出最坏情形下的渐近上界，辅助空间不计输入和最终输出。

      算法时间辅助空间主要开销
      KruskalO(N + E·α(N))O(N + E)打乱墙列表、并查集操作
      PrimO(N + E log(E + 1))O(N + E)候选墙的堆操作
      BFS 非递归O(N)O(N)访问表、父节点表、显式队列
      BFS 递归O(N)O(N)各层前沿、访问表、父节点表。栈深取决于处理的层数
      DFS 非递归O(N)O(N)访问表、父节点表、显式栈
      DFS 递归O(N)O(N)访问表、父节点表。栈深取决于搜索深度

      α 为反阿克曼函数，并查集单次操作的复杂度按摊还计算。仓库 CSV 测量耗时与访问格数，空间复杂度来自对源码的分析。

      数据来自白荷初的性能测试，见仓库 docs/perf_results.csv 与 docs/loop_results.csv。

      网页是怎么跑起来的

      C++ 算法源码
      src/maze_generator.cpp（李婷婷：并查集、Kruskal、Prim）
      src/maze_solver.cpp（方雨婷：BFS、DFS 各两种写法）
      ▼
      编译成 WebAssembly
      用 clang（wasi-sdk）把上面两份源码原样编译，web/wasm_api.cpp 只负责把结果交给网页，不改算法
      ▼
      浏览器里运行
      网页（JavaScript + Canvas）只负责画图和交互；每次生成、求解都是在调用这段 C++ 代码

      分工

      李婷婷迷宫生成：并查集、Kruskal、Prim（堆）、种子与环路
      方雨婷迷宫求解：BFS / DFS 递归与非递归；Qt 界面与网页界面
      白荷初正确性测试、性能测试、对比分析与报告

      同一份 C++ 代码也有 Qt 桌面版（仓库根目录 CMake 工程）。两边功能一致，迷宫的随机结果因标准库实现不同可能不一样。
